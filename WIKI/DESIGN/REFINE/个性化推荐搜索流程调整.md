# 总体目标
- 将检索职责区分清晰：
  - RAG：基于内部已爬取/已结构化的数据，重点利用“用户个性化信息（项目/地域/品牌/客群）”做精准项目检索和推荐。
  - Web：作为RAG之后的补充链路，围绕RAG命中结果进行“外部实时信息补充”，诸如官方公告、新闻、最新进展、官网、甲方招采平台页面等。
- 在 generate_query 节点引入 LLM 组合逻辑，让 LLM 结合“用户原始问题 + 用户推荐项目”产出更高质量的“推荐关键词/个性化查询”，再与计划查询融合，用于 RAG 优先检索。
- 保留完整降级路径：无用户信息/无推荐结果/LLM异常 → 回退启发式关键词提取（你刚优化的函数）→ 再不行则回到原计划查询。

# 流程设计（阶段划分）
1) 阶段A：查询生成（generate_query）
- 输入：用户自然语言问题、HITL核准后的 research_plan（如果有）、用户推荐项目（query_user_recommend）、历史记忆（后续集成mem0）
- 新增步骤：LLM个性化关键词组合
  - 目的：综合用户问题与推荐项目，产出“推荐关键词列表”
  - 产物：state.user_recommend_keywords（缓存）
- 融合策略：
  - 从 plan 的 planned_queries 选出首轮查询（遵守并发上限）
  - 将 LLM 推荐关键词按“个性化比例/Top-K”融合到 RAG 查询中（可采用“suffix拼接/实体替换/双语增强”混合策略）
  - 形成两套集合：
    - rag_queries：个性化增强后的查询（主用于 RAG）
    - web_queries_initial：初始Web查询（可为空或较少，仅在RAG为0命中时应急）

2) 阶段B：RAG优先检索（rag_search + mem_search）
- 并发执行 rag_search（基于 REST）与 mem_search（内部记忆渠道）
- 输出：结构化的RAG候选源（项目、地域、甲方、时间、链接、摘要等）
- 重排：本地规则 + VoyageAI（按你的配置 defer_api_rerank_to_reflection 决定在反思或当前节点）
- 若RAG为空或不足阈值 → 回退触发 Web 初次检索（用 web_queries_initial 补救）

3) 阶段C：Web补充检索（web_research）
- 触发条件：RAG有结果后（主流路径），从RAG Top-N源中抽取实体字段（甲方、项目名、地域、平台等），生成“补充性Web查询”
  - 典型补充：官网链接、招采平台公示页、新闻/舆情、社交媒体、投标FAQ/答疑公告等
- 并发控制：soft timeout + 最大并发
- 结果合并：与RAG源合并去重，然后交给 reflection 进行归纳、证据标注与再排序

4) 阶段D：Reflection与Finalization
- Reflection 阶段执行最终重排（VoyageAI）与证据选择
- Finalize_answer 输出结构化报告/摘要，并记录thinking/引用

# LLM组合与查询融合策略
- LLM输出一组“推荐关键词/子查询”（多语言混合可行，优先保持原语义）
- 融合方式：
  - Suffix拼接：原 planned_query + “ ” + best_keyword（优先取地点/品牌/机构类）
  - 实体替换：将 planned_query 中的通用词替换为 LLM建议的更具体实体（如“酒店项目”→“精品酒店 西安 CCBD 项目”）
  - 双语增强：如果原查询是中文而 Keyword 是英文品牌/缩写，平行附加（“酒店 招投标 CCBD Hilton”）
- 融合比例由 `personalization_query_ratio` 控制，如 ratio=0.6，首N个查询使用增强版
- 保障：保留至少1-2个“通用查询”，避免过拟合个性化导致召回缺失

# RAG→Web 补充查询的生成
- 从 RAG Top-N 结果抽取字段：project_name、party_a_name、region/city、platform（如ggzy.gov.cn）、date
- 生成 Web 补充查询模板（可配置）：
  - “{project_name} 招标公告 官方网站”
  - “{party_a_name} {project_name} 公示”
  - “{project_name} 新闻 进展”
  - “{party_a_name} 招采平台”
- 限制每项补充查询总量（web_supplement_limit），并去重
- Soft timeout，避免Web补充拖慢总体时延

# 提示词草案（prompts.py）
函数：`recommend_keyword_composer_instructions`
- 目标：阅读“用户问题 + 用户推荐项目（bullet）”，输出最多 Top-K 个“推荐关键词/子查询”，JSON结构化输出，兼顾中英文实体，优先抽取地域/品牌/甲方/平台等实体，避免隐私词。
- 变量：{user_question} {user_projects_context} {current_date} {language} {top_k}
- 约束：不输出解释，仅输出字段 `{"query": ["...", "..."]}`

# 简要伪代码（graph.py 关键段）
```python
def _compose_recommend_keywords_llm(self, user_question, user_projects_context):
    if not self.config.enable_llm_personalization or not user_projects_context:
        return []

    if cache := self.state.get("user_recommend_keywords"):
        return cache

    prompt = recommend_keyword_composer_instructions.format(
        user_question=user_question,
        user_projects_context=user_projects_context,
        current_date=get_current_date(),
        language="zh",
        top_k=self.config.llm_personalization_top_k,
    )
    try:
        llm = ChatGoogleGenerativeAI(model=self.config.llm_personalization_model, ...)
        structured_llm = llm.with_structured_output(SearchQueryList)
        result = structured_llm.invoke(prompt)
        keywords = list(result.query or [])
    except Exception:
        keywords = self._extract_project_keywords(user_projects_context)  # fallback

    self.state["user_recommend_keywords"] = keywords
    return keywords
```
