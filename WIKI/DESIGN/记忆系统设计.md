## 📋 记忆系统设计方案

### 🎯 设计目标
为LangGraph研究助手工作流集成基于mem0的记忆能力，实现用户和助手的分离式记忆管理，提升对话连续性和个性化体验。

### 🏗️ 架构设计

#### 1. **记忆分层结构**
```
记忆系统 (当前阶段实现)
├── User Memory (用户记忆)
│   ├── 偏好设置 (研究深度、关注领域(Y)、输出格式等)
│   ├── 历史查询 (查询模式、关键词、研究主题(Y))
│   ├── 反馈记录 (对答案质量的评价、改进建议(Y))
│   └── 上下文信息(Y) (当前项目、工作背景、专业领域)
│
└── Assistant Memory (助手记忆)
    ├── 研究策略(G) (有效的查询组合、搜索模式) - 后期工程化
    ├── 知识图谱(Y) (主题关联、概念映射)
    ├── 性能优化(G) (成功的工作流路径、时间消耗分析) - 后期工程化
    └── 错误学习(G) (失败案例、改进方案) - 后期工程化

注：Y=当前实现，G=后期工程化
```

#### 2. **集成点设计 (当前阶段)**
在现有LangGraph工作流的关键节点集成记忆功能：

**A. 查询生成阶段 (generate_query)**
- **读取记忆(Y)**: 用户历史查询主题、关注领域
- **写入记忆(Y)**: 用户当前查询主题、研究背景

**B. 反思分析阶段 (reflection)**  
- **读取记忆(Y)**: 用户上下文信息、专业领域
- **写入记忆(Y)**: 发现的主题关联、概念映射

**C. 答案合成阶段 (finalize_answer)**
- **读取记忆(Y)**: 用户偏好的输出格式
- **写入记忆(Y)**: 用户反馈、研究主题总结

#### 4. **工作流集成策略**

**阶段1: 启动增强 (Y)**
- 在`startup_thinking`前检索用户上下文和兴趣主题
- 根据用户关注领域优化初始查询方向
- 基于历史查询主题提供背景信息

**阶段2: 中间增强 (Y)**  
- 在`reflection`节点中融入用户专业背景
- 利用知识图谱发现相关主题和概念
- 根据用户反馈历史调整分析深度

**阶段3: 结果个性化 (Y)**
- 在`finalize_answer`中应用用户偏好的输出格式
- 保存新发现的主题关联到知识图谱
- 收集用户反馈并更新偏好设置

**后期扩展 (G)**
- 动态工作流路径优化
- 智能参数调整
- 自适应查询策略

#### 5. **数据流设计**

```
用户查询 → 记忆检索 → 个性化配置 → LangGraph工作流
    ↓                                        ↓
记忆更新 ← 反馈收集 ← 结果输出 ← 研究完成
```

### 🔧 实现考虑

1. **性能优化**: 记忆检索异步化，避免阻塞主工作流
2. **隐私保护**: 用户记忆加密存储，支持数据删除
3. **扩展性**: 支持多种记忆类型，便于后续功能扩展
4. **容错机制**: 记忆服务异常时不影响核心研究功能

### 💡 预期效果

1. **个性化体验**: 根据用户历史调整研究策略和输出格式
2. **效率提升**: 基于成功模式优化查询生成和循环控制  
3. **持续学习**: 助手记忆积累提升整体研究质量
4. **上下文连续**: 跨会话保持研究主题和偏好设置
