# 智能研究助手流程设计

## 核心设计理念

本系统采用**意图驱动的多路径架构**，通过智能意图分类将用户查询路由到最适合的处理流程，实现高效精准的信息检索和研究。

## 统一意图分类入口

### classify_intent 设计
- **统一入口**：所有用户查询（包括追问）都经过统一的意图分类
- **上下文感知**：支持追问上下文，结合历史对话进行智能分析
- **要素完整性检查**：自动检测时间、地点、主体、事件等关键要素
- **澄清机制**：当关键信息缺失时，主动引导用户提供更多细节

## 三大主处理分支

### 1. Deep Research (深度研究)
**适用场景**：复杂主题、行业分析、多步骤研究
**核心流程**：
```
thinking_startup_stage → generate_query → [web_research + rag_search] → reflection → 
(loop: thinking_middle_stage → generate_query → [web_research + rag_search] → reflection) → 
thinking_finalization_stage → generate_enhanced_report
```

### 2. Answer Simple Fact (简单事实回答)
**适用场景**：基础知识问答、计算、概念解释
**特点**：
- 直接使用LLM回答，无需外部搜索
- 支持对话模式，允许连续提问
- 智能识别聊天场景，提供友好交互

### 3. Direct Lookup (直接查询)
**适用场景**：实时信息、官方数据、特定网站查询
**流程**：
- 自动发现目标实体的官方网站
- 限制搜索范围到权威源
- 快速返回准确信息

## 核心创新：并行搜索架构

### RAG + Web 并行设计
在深度研究的 `generate_query` 阶段，系统采用**并行搜索策略**：

```python
# 每个查询同时触发两种搜索
Send("web_research", {"search_query": q})      # 网络搜索
Send("rag_search", {"search_query": q})        # 知识库搜索
```

**优势**：
- **信息覆盖更全面**：结合实时网络信息和结构化知识库
- **提高搜索效率**：并行执行减少总体耗时
- **灵活配置**：通过 `enable_rag` 参数控制是否启用RAG搜索
- **智能合并**：reflection节点统一处理多源搜索结果

## 设计优势对比

### 相比市面其他Agent的优势

1. **智能路由机制**
   - 其他：单一处理流程或简单规则分流
   - 本系统：LLM驱动的智能意图分类 + 要素完整性检查

2. **多源信息融合**
   - 其他：通常只使用单一信息源
   - 本系统：web搜索 + RAG搜索并行，信息更全面

3. **上下文连续性**
   - 其他：每次查询独立处理
   - 本系统：追问感知，结合历史上下文进行分析

4. **自适应研究深度**
   - 其他：固定研究流程
   - 本系统：基于完成度和努力级别动态调整并行度和研究深度

5. **人机协作设计**
   - 其他：全自动或简单确认
   - 本系统：关键节点支持人工干预，研究计划可审批修改

6. **结构化思考**
   - 其他：直接搜索-回答模式
   - 本系统：startup → middle → finalization 三阶段结构化思考
